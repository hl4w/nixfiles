# HL4W Architecture

**Version: v0.0.5**

## Overview

HL4W NixOS configuration follows a modular, host-specific structure that allows managing multiple machines from a single repository. Based on NixOS 26.05 with Hyprland/Niri window managers, using Lix as the high-performance Nix implementation.

## Flake Structure

`flake.nix` is the project's entry configuration file, defining the complete build environment:

### Inputs

| Input | URL | Description |
|-------|-----|-------------|
| `nixpkgs` | `github:NixOS/nixpkgs/nixos-26.05` | NixOS 26.05 stable |
| `home-manager` | `github:nix-community/home-manager/release-26.05` | Home Manager, synced with nixpkgs version |
| `hyprnix` | `github:hyprwm/hyprnix/main` | Hyprland toolchain for managing Hyprland configuration |

### Global Configuration (nixConfig)

- **Binary Cache Substituters**: Configured with Chinese mirrors for faster downloads
  - USTC (primary): `https://mirrors.ustc.edu.cn/nix-channels/store`
  - Tsinghua: `https://mirrors.tuna.tsinghua.edu.cn/nix-channels/store`
  - BFSU: `https://mirrors.bfsu.edu.cn/nix-channels/store`
  - Official (fallback): `https://cache.nixos.org`
- **Experimental Features**: Enables `nix-command` and `flakes`
- **Store Optimization**: Enables `auto-optimise-store`

### Host Configuration Generator (mkHost)

The `mkHost` function generates unified host configurations:

```nix
mkHost = name: nixpkgs.lib.nixosSystem {
  system = "x86_64-linux";
  modules = [
    ./hosts/${name}/configuration.nix  # Host-specific configuration
    home-manager.nixosModules.home-manager
    {
      home-manager.users.${USERNAME} = import ./home/hosts/${name}.nix;
    }
  ];
  specialArgs = {
    inherit inputs;
    nixSubstituters = substituters;
    nixTrustedPublicKeys = trusted-public-keys;
  };
};
```

### Outputs

- **nixosConfigurations**: Host configuration outputs (dynamically generated by install script)

### Adding a New Host

**Method 1: Using install.sh (Recommended)**

```bash
./scripts/install.sh
```

The script will guide you through:
1. Enter username, hostname, Git info
2. Select host type (Desktop/Laptop/Server)
3. Select window manager (Hyprland/Niri)
4. Select desktop shell (DMS-Shell/Noctalia-Shell)
5. Select polkit agent (KDE/Hyprland)
6. Auto-generate configuration files

**Method 2: Manual**

1. Create a new directory in `hosts/`
2. Add `configuration.nix` (see `templates/host-template/` for reference)
3. Generate `hardware-configuration.nix` using `nixos-generate-config --show-hardware-config > hosts/your-host/hardware-configuration.nix`
4. Add the host to `flake.nix` under `nixosConfigurations`
5. Create a corresponding home configuration in `home/hosts/`

## Configuration Flow

1. `flake.nix` → defines inputs, outputs, and Chinese mirrors
2. Host `configuration.nix` → imports system modules
3. System modules → configure system services and packages
4. Home Manager → imports user modules
5. User modules → configure user-specific settings

### Wallpaper Auto-color System

This configuration includes a wallpaper auto-color system using `pywal`:

- **Feature**: Extract colors from wallpaper and apply them dynamically to:
  - Terminal (alacritty, kitty, foot)
  - Shell prompt (Starship)
  - Neovim/Emacs editors
  - GTK/Qt applications

- **Scripts**:
  - `scripts/wallpaper-color.sh`: Main script for wallpaper color extraction
  - `wp-color`: Set specified wallpaper and apply colors
  - `wp-random`: Randomly select wallpaper from `~/.wallpapers/`
  - `wp-apply`: Apply current colors without changing wallpaper
  - `wp-list`: List available wallpapers

- **Integration**:
  - Colors stored in `~/.cache/wal/`
  - Loaded automatically in `home/common/shell.nix`
  - Works seamlessly with DMS-Shell and Noctalia-Shell

### Day/Night Theme Switching

The unified theme system supports automatic day/night theme switching:

- **Feature**: Automatically switch between light and dark themes based on time
  - Day mode (6:00-18:00): Adwaita (light), Papirus icons
  - Night mode (18:00-6:00): Adwaita-dark, Papirus-Dark icons

- **Commands**:
  - `theme-auto`: Auto-switch based on current time
  - `theme-dark`: Force dark mode
  - `theme-light`: Force light mode

- **Configuration** (in host configuration):
  ```nix
  desktop.unified-theme = {
    themeMode = "auto";    # dark/light/auto
    dayStart = 6;          # Day start hour
    nightStart = 18;       # Night start hour
  };
  ```

- **Implementation**:
  - Managed by `modules/desktops/unified-theme.nix`
  - Scripts created via `pkgs.writeScriptBin`
  - Theme applied to GTK, Qt, Shell, and SDDM

### Desktop Configuration Module

The desktop configuration module `modules/desktops/desktop.nix` supports dynamic selection of window manager, desktop shell, and polkit agent:

- **Configuration Options**:
  ```nix
  desktop = {
    windowManager = "hyprland";  # Options: "hyprland" or "niri"
    shell = "dms";               # Options: "dms" or "noctalia"
    enableInputMethod = true;     # Enable input method
    polkitAgent = "kde";         # Options: "kde" or "hyprland"
  };
  ```

- **Window Manager and Shell Combinations**:
  | Window Manager | Desktop Shell | Description |
  |----------------|---------------|-------------|
  | hyprland | dms | Lightweight combination, performance focused |
  | hyprland | noctalia | Modern integrated experience |
  | niri | dms | Lightweight combination, good for laptops |
  | niri | noctalia | Modern tiling + integrated shell |

- **Polkit Agent Selection**:
  | Option | Package | Description |
  |--------|---------|-------------|
  | kde | `kdePackages.polkit-kde-agent-1` | KDE-style authentication agent, full-featured |
  | hyprland | `hyprpolkitagent` | Hyprland native agent, more lightweight |

- **Qt6 Theme Tools**:
  - `qt6Packages.adwaita-qt`: Qt6 Adwaita theme
  - `adwaita-qt`: Qt5 Adwaita theme (compatibility)
  - `gnome.adwaita-icon-theme`: Adwaita icon theme
  - `gnome.gnome-themes-extra`: GTK theme support

- **Implementation**: Dynamically imports corresponding modules based on configuration, no manual imports needed

### Wallpaper Auto-color (pywal)

The configuration uses `pywal` to extract colors from wallpaper and apply them to various applications:

- **Commands**:
  - `wp-color -s <wallpaper>`: Set wallpaper and apply colors
  - `wp-random`: Randomly select from wallpaper directory
  - `wp-apply`: Apply current colors without changing wallpaper
  - `wp-list`: List available wallpapers

- **Wallpaper Directory**:
  - Project: `wallpapers/`
  - User: `~/.wallpapers/` (automatically synced from project)
  - Default: `default.jpg` (Chinese-style majestic landscape dark theme)

- **Auto Watcher**:
  - A background service (`wallpaper-watcher`) monitors wallpaper changes
  - Automatically triggers color scheme update when wallpaper changes via Shell GUI

- **Applied To**:
  - Terminal (Alacritty, Kitty, Foot)
  - Starship prompt
  - Neovim editor
  - Noctalia-Shell and DMS-Shell

- **Implementation**:
  - Script: `scripts/wallpaper-color.sh`
  - Watcher: `scripts/wallpaper-watcher.sh`
  - User service: `home/common/wallpaper-watcher.nix`

### Spell Checker

System-level spell check support:

- **Spell Check Engine**: `nuspell` (3x faster than Hunspell, fully compatible with Hunspell dictionary format)
- **English Dictionaries**: `hunspellDicts.en-us` (US), `hunspellDicts.en-gb-ise` (UK)

### Lix High-Performance Nix Implementation

This configuration uses **Lix** as an alternative implementation of the Nix package manager:

- **Lix Advantages**:
  - Faster than native Nix (especially in eval and fetch scenarios)
  - Fully compatible with all Nix features (flakes, nix-command, etc.)
  - Community-driven, actively developed
  - Rewritten in C++ for better performance

- **Configuration**:
  ```nix
  # Use Lix stable version
  nix.package = pkgs.lixPackageSets.stable.lix;
  ```

- **Overlay Configuration**: Use `nixpkgs.overlays` to ensure Nix-dependent tools (like nixpkgs-review, nix-eval-jobs) also use Lix

- **Verification**:
  ```bash
  nix --version
  # Output: nix (Lix, like Nix) 2.x.x
  ```

### Mouse Side Buttons Configuration

This configuration supports mouse side buttons (Button 8/9) for back/forward navigation in applications:

- **Implementation modules**: `modules/hardware/mouse.nix` and `modules/desktops/hyprland.nix`
- **Handling strategy**: Use `pass` command to pass mouse events to applications

- **Mouse button numbering**:
  - Button 1: Left click
  - Button 2: Middle click (scroll wheel press)
  - Button 3: Right click
  - Button 4/5: Scroll up/down
  - Button 6/7: Scroll tilt (some mice)
  - Button 8/9: Side buttons (back/forward)

- **Hyprland configuration**:
  ```nix
  binds = {
    "mouse,1" = "movewindow";   # Left click to move window
    "mouse,2" = "resizewindow"; # Middle click to resize
    "mouse,3" = "togglefloating"; # Right click to toggle floating
    "mouse,8" = "pass";         # Side button back - pass to application
    "mouse,9" = "pass";         # Side button forward - pass to application
  };
  ```

- **Supported applications**:
  - Nemo file manager: Back/forward directories
  - Firefox/Chrome browsers: Back/forward pages
  - Other GTK/Qt applications

## Build Process

### Initial Installation

```bash
# Use installation script for initial installation
./scripts/install.sh
```

### System Updates

After installation, if you modify any Nix modules, you can directly update the system using the following commands:

```bash
# Update system (use after modifying modules/ directory)
sudo nixos-rebuild switch --flake .#<hostname>

# Update Home Manager user configuration (use after modifying home/ directory)
home-manager switch --flake .#<username>@<hostname>

# Update flake inputs (upgrade dependency versions like nixpkgs)
nix flake update

# One-click update using script (includes flake update and system rebuild)
./scripts/update.sh
```

### Verification and Rollback

```bash
# Check configuration syntax
nix flake check

# Test build (no deployment)
nix build .#<hostname>

# Preview changes
nixos-rebuild dry-activate --flake .#<hostname>

# Rollback to previous generation
sudo nixos-rebuild switch --rollback

# Clean old generations
./scripts/clean.sh
```
